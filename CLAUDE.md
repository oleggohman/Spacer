# Spacer

A native macOS disk usage treemap app. It is a SwiftUI app built as a Swift Package: there is no .xcodeproj, and everything builds and tests from the command line. It needs macOS 15+ and Swift 6 with strict concurrency. Its one third-party dependency is Sparkle (auto-update), used only by the `Spacer` executable: `AppUpdater` wraps `SPUStandardUpdaterController` and adds Check for Updates… to the app menu, and runs only when `AutoUpdate.isConfigured` (SpacerCore) finds an app bundle with `SUFeedURL` and `SUPublicEDKey`, so `swift run` builds skip it.

## Package layout

- `Sources/SpacerCore` (library): all the logic. This covers the file tree model (`FileNode`), the scanner (`DiskScanner`, which reads folders with `getattrlistbulk` through `DirectoryReader` and sends a preview tree with its progress), the squarified layout (`TreemapLayout`), hit testing (`TreemapHitTest`), deletion (`DeletionService`), app state (`ScanSession`, @Observable and @MainActor), file categories and colors (`FileCategory`, `MapPalette`), per-folder category bytes (`CategoryStats`), the map legend and category highlight (`CategoryLegend`, `CategoryHighlight`), byte formatting, recent scans and inspector details, the scan summary and unreadable folders (`ScanSummary`, `UnreadableFolders`), and the keyboard, VoiceOver and tooltip helpers (`TreemapNavigation`).
- `Sources/Spacer` (executable): thin SwiftUI views (sidebar, toolbar, scan progress, inspector, Canvas-based `TreemapView`, category legend bar `CategoryLegendBar`) that read and drive `ScanSession`.
- `Tests/SpacerCoreTests`: Swift Testing (`@Test`, `#expect`) tests for SpacerCore. Filesystem tests build temp trees under `FileManager.temporaryDirectory` and remove them afterwards. One exception tests no SpacerCore code: `PPPCProfileTemplateTests` reads `Resources/` through `#filePath` to keep the PPPC template in step with `Info.plist`.
- `scripts/bundle.sh` + `Resources/Info.plist`: wrap the release binary into `build/Spacer.app` (ad-hoc signed, or Developer ID signed with the hardened runtime when `SIGN_IDENTITY` is set). It copies the committed `Resources/AppIcon.icns`, which `scripts/make-icon.sh` writes by running `scripts/make-icon.swift` (draws the icon at every .iconset size); rerun it only when that script changes. It also embeds `Sparkle.framework` in `Contents/Frameworks` (the binary has an `@executable_path/../Frameworks` rpath) and, with a Developer ID, signs Sparkle's XPC services, Autoupdate and Updater.app, then the framework, then the app.
- `scripts/release.sh prepare|publish`: cuts a release (needs `SIGN_IDENTITY`, or `ALLOW_ADHOC=1`); `publish` uses `scripts/make-dmg.sh --skip-build` to sign the DMG. The DMG is notarized and stapled only with `NOTARIZE=1`, which also needs `NOTARY_PROFILE`; by default it is not notarized. For Developer ID releases, `publish` then runs `scripts/make-appcast.sh`, which signs the final DMG with Sparkle's `sign_update` (EdDSA private key in the login keychain, account `com.oleggohman.spacer`) and writes `build/appcast.xml`, attached to the GitHub release; the app reads it from `SUFeedURL` (`https://github.com/oleggohman/Spacer/releases/latest/download/appcast.xml`). The build number (`CFBundleVersion`) is what Sparkle compares, and `version.sh` bumps it with every version change. `scripts/make-pppc-profile.sh` fills `Resources/Profiles/Spacer-PPPC.mobileconfig.template` with the Developer ID signed app's designated requirement and writes `build/Spacer-PPPC.mobileconfig`, the PPPC profile for MDM-managed Macs. `scripts/lib/signing.sh` holds the one Developer ID check (`is_developer_id_requirement`, `is_developer_id_signed`) and the designated requirement parser that bundle.sh, make-dmg.sh, make-pppc-profile.sh and release.sh source; `scripts/lib/check.sh` holds the shell tests' `check`/`finish`.

## Rules

- Put logic in SpacerCore and cover it with tests. Views stay thin. When a view needs a computed helper, move it to SpacerCore and test it there.
- Every delete must go through `DeletionService` (via `ScanSession.delete`), which applies the guard rails: it refuses the scan root, volume roots, the home folder, system prefixes (/System, /usr, /bin, /sbin, /Library), Apple apps in /Applications, any folder that contains one of these (or a mounted volume, /Applications, /private/etc, /private/var, /private/tmp), and anything outside the scan root. Never call `FileManager.removeItem`/`trashItem` on user items anywhere else. After a delete, update the tree with `FileNode.remove()` instead of rescanning.
- Deletion returns a result per item and never throws for the whole batch.
- The tree is changed in place, and views use `ScanSession.treeVersion` as their layout and refresh key. Any tree change must bump it; `ScanSession.delete` and `ScanSession.undoLastTrash` are the only places that do this today, so change the tree through them.
- Each folder keeps the bytes per file category of its subtree (`FileNode.categoryStats`, a `CategoryStats`); `colorCategory` (a plain folder's `dominantCategory`) is the category the highlight matches; plain folders are drawn neutral. A folder sums what its children add: a file its size under its category, an app bundle (`FileNode.isAppBundle`) its whole size under `.apps`, a plain folder its own stats. So an app bundle's own stats show its real content (the legend when zoomed into it), while it is drawn as an app and counts as apps in its parent (/Applications reads purple). For a full scan the stats add up to the folder's size. Only listed files count, so a scan preview folder can have no dominant category and the legend shows the rest as "not listed yet". `FileNode.remove()` subtracts the removed bytes (switching to `.apps` above an app bundle), so `ScanSession.delete` keeps the stats right without a rescan.
- Highlight state lives in `ScanSession`: `highlightedCategory` (`toggleHighlight`), cleared by `start(url:)` and by `setLegendVisible(false)`; `isLegendVisible` drives the View menu's Show/Hide Legend item. `TreemapView` fades blocks with `CategoryHighlight.matches(_:category:root:)` and `faded`, and colors headers with `headerText`. Inside an app bundle below the map's root everything matches only `.apps`, matching what the root's legend counts; elsewhere blocks match their `colorCategory` and headers match any bytes of the category.
- Map colors come from `FileCategory.color(darkMode:)` (Apple's Storage palette in `MapPalette`, one flat color per category, no depth step) and `MapPalette.folderFill(depth:darkMode:)` (neutral folders, a small step per depth, clamped at `maxShadedDepth`); `FileCategory.fill(for:depth:darkMode:)` picks between them. Labels come from `RGBColor.labelColor` (white or `MapPalette.darkLabel`), drawn at full opacity. Tests hold every category color and folder fill (depths 0–6, both modes) to 4.5:1 against its label; faded blocks and the dimmer size text are exempt. Chrome uses SwiftUI semantic colors only and system fonts, with no text under 11 pt outside map labels.
- "N small items" blocks in the layout carry their parent folder as `node`, but stand for several items. Views use `TreemapHitTest.node(at:)`, which returns nil for them, for hover, selection and file actions.
- The PPPC template keeps its top-level `PayloadIdentifier` (`com.oleggohman.spacer.pppc`) fixed, so an installed profile is replaced instead of duplicated, and both `PayloadUUID`s fixed. Every service entry has `Identifier` = `CFBundleIdentifier` from `Resources/Info.plist` and `CodeRequirement` = `__CODE_REQUIREMENT__`; `PPPCProfileTemplateTests` checks this, so change both files together. `make-pppc-profile.sh` finds services by their `<key>SystemPolicy…</key>` lines and refuses any signature that is not Developer ID Application.
- `publish` makes everything that can fail (the PPPC profile, the signed DMG and, with `NOTARIZE=1`, its notarization) before it commits and tags, and ships only the app `prepare` built (CDHash, signing mode and notarization setting are recorded in `build/release-state`; publish refuses a different `ALLOW_ADHOC` or `NOTARIZE` setting). Keep that order; `scripts/test-release.sh` checks it, and `prepare` runs it and `scripts/test-pppc-profile.sh` before it builds.
- Sizes are allocated bytes (`ATTR_FILE_ALLOCSIZE`). Hard links count once (`seenIdentities`). APFS clones count only their own bytes (`DirectoryEntry.countedSize`): a clone is a file whose `ATTR_CMNEXT_CLONEID` is not its own inode, and its `ATTR_CMNEXT_PRIVATESIZE` is read per file for those only, because asking for it on every file made a full-disk scan about 1.5x slower. The original counts in full. When the original is deleted, the survivors keep its inode as clone ID and none reports the shared blocks as private, so a clone whose clone-ID inode no longer exists (`/.vol/<dev>/<id>` stat, clones only; `isOrphanedClone`) is counted in full by the first one seen per (device, clone ID), through `seenIdentities`, and by its private bytes after that. This is an approximation: a clone whose original still exists outside the scan shows only its own bytes, and a clone written after cloning gets a new clone ID and counts in full, so the blocks it still shares are counted again. If the original still exists but was truncated or overwritten, its clones can share blocks with each other yet report 0 private bytes, and the orphan check does not fire (the inode exists), so those shared blocks are missing from the total. Deleting the node that carries an orphaned group's shared bytes subtracts all of them (`FileNode.remove()`), while surviving clones still hold the blocks, so the freed figure and the totals are off for that group until a rescan; fixing this needs clone-group identity on every node, which is not worth the memory. Folders are skipped when they are mount points, not by device number (firmlinks may report another device).
- Unreadable folders are collected in `ScanSession.finish` (`FileNode.unreadableFolders()`, `UnreadableFolders`; delete and undo update the list with `removing(under:)` and `adding(_:)`) and shown as a warning line, never as a size; the inspector says "Size unknown" for them.
- Move to Trash is undone only through `ScanSession.undoLastTrash` (`DeletionService.restore`, then `FileNode.attach`), which bumps `treeVersion`. A new scan, a permanent delete, `dismissUndo()` (the banner calls it when it auto-dismisses or is closed) and a completed undo clear `undoableTrash`; a new Move to Trash replaces it. Move to Trash gives no undo when the system reports no Trash location for a removed item. A scan started while a delete or undo runs keeps no `retainedScan` (the delete ends early on the new generation), and the toolbar and sidebar disable scanning while `isDeleting`.
- A same-location rescan keeps the previous tree in `retainedScan` until the scan finishes or is stopped (`cancel()` brings it back; so does a failed rescan, which also sets `rescanFailure` for an alert). This is the one case where memory doubles.
- `smallItemsGroup` is the only way a "N small items" block reaches the inspector, and the group inspector is read-only.
- Keyboard and VoiceOver helpers (sibling neighbors, first block, accessible blocks, tooltip placement) live in `TreemapNavigation`; views call them and do not compute their own.

## Commands

```bash
swift build
swift test
swift test --enable-code-coverage
swift format lint --recursive --strict Sources Tests
swift build -c release -Xswiftc -warnings-as-errors
scripts/bundle.sh && plutil -lint build/Spacer.app/Contents/Info.plist
scripts/test-pppc-profile.sh   # make-pppc-profile.sh with a stub codesign
scripts/test-release.sh        # release.sh publish in throwaway repo copies with stubs
```

Coverage for SpacerCore (target 80%+):

```bash
BIN=$(swift build --show-bin-path)
xcrun llvm-cov report "$BIN/SpacerCoreTests.xctest/Contents/MacOS/SpacerCoreTests" \
  -instr-profile "$BIN/codecov/default.profdata" Sources/SpacerCore
```
